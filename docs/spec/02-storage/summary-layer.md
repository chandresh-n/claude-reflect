# Summary layer

## Role

The summary layer is a collection of LLM-maintained markdown pages that
synthesize views over the canonical layers (sessions, decisions, gap
records, archive entries). It is regenerable and is not a source of
truth. Consumers read it for orientation, semantic retrieval, and
navigation, not for authoritative judgments.

## Inputs

Written exclusively by the maintenance process (see
`04-processes/maintenance.md`), which reads the canonical layers and
produces the synthesized pages.

## Outputs

Read by:

- The proposer, for orientation and semantic context ("what have we
  learned about gaps of this kind?").
- The human, when reviewing the state of the knowledge base.

Agents making decisions that depend on precise current state read
canonical sources, not the summary layer. The summary layer informs; it
does not authoritatively answer.

## Storage model

All pages are plain markdown files in a dedicated directory within the
knowledge base. Git tracks them (so page evolution is itself auditable).

## Page kinds

The initial set. The taxonomy is living, not closed: maintenance may
introduce new page kinds when it identifies a pattern worth anchoring.

### Gap-kind pages

One page per distinct `kind` currently in use across gap records.

- Anchor: the kind label.
- Content: characterization of the kind, list of gap records of this
  kind, historical proposals targeting them (with outcomes), what has
  worked and what has not, proposer-facing notes on approaches that
  have or have not succeeded.

### Archive-entry pages

One page per archive entry.

- Anchor: the archive entry identifier.
- Content: the `qualitative_position` prose (written by maintenance
  when `active_at` closes), summary of gaps observed under this
  configuration, distinguishing characteristics.

### Exploration-profile page

One page, always current.

- Anchor: the current state of exploration.
- Content: surfaces recently touched by proposals, count-profile posture
  (generalization vs. specialization), recent semantic focus of
  proposals, neglected regions. Consulted by forced-novelty reasoning.

### Gap-dashboard page

One page, always current.

- Anchor: current state of active gaps.
- Content: ranked list of open gaps with evidence pointers and links to
  gap-kind pages. Ranked by frequency × recency × magnitude considered
  jointly (the proposer must not collapse these to a single axis).
  Used by the proposer for navigation, not as authoritative
  prioritization input.

### Session-cluster pages

Emergent. Created by maintenance when it identifies a group of sessions
sharing a pattern worth its own page.

- Anchor: a pattern description.
- Content: list of matching sessions, shared-shape narrative, links to
  relevant gap records.

### Decision-lineage pages

Emergent. Created by maintenance when it identifies a chain of related
decisions.

- Anchor: a lineage description (e.g., "evolution of the file-location
  skills").
- Content: the chain in temporal order, relationships between
  decisions, whether predictions held (when verification is built),
  overall trajectory.

## The index

A top-level markdown file at the root of the summary layer directory,
regenerated by maintenance on every pass. Organized into sections, one
per page-kind. Under each section: the pages of that kind, each with a
short summary, anchor, last-updated timestamp, and link.

Structure:

```
# Summary Layer Index

Last updated: <timestamp>

## Gap-kind pages
  - <page>, <kind label>, <last updated>
  - ...

## Archive-entry pages
  - <page>, <entry id>, <last updated>
  - ...

## Exploration-profile
  - exploration-profile.md, <last updated>

## Gap-dashboard
  - gap-dashboard.md, <last updated>

## Session-cluster pages
  - <page>, <pattern>, <last updated>
  - ...

## Decision-lineage pages
  - <page>, <lineage>, <last updated>
  - ...
```

Each page appears under exactly one page-kind section.

## Page requirements

Every page must:

- Have a filename that identifies its anchor unambiguously.
- Begin with a "Last updated" line.
- Include a "Generated from" line naming the canonical sources the page
  was synthesized from.
- Cite sources for every factual claim. Citations resolve to session
  identifiers (with turn ranges), decision identifiers, gap
  identifiers, or archive entry identifiers.
- Use clear headings and consistent conventions so LLM readers can
  navigate efficiently.
- Link to other pages when referencing concepts that have their own
  page.

Pages must not:

- Re-state information that lives authoritatively elsewhere. Summarize
  and link; do not duplicate.
- Produce scalar grades.
- Make claims without citations.
- Duplicate content across pages. Each piece of synthesis lives on one
  page; others link to it.

## Invariants

- Every citation on every page resolves to a real source.
- The exploration-profile page and the gap-dashboard page always exist
  and are current within one maintenance cycle of the latest canonical
  content.
- Pages whose underlying sources have been superseded (e.g., a
  gap-kind page whose kind has been reconciled) are updated or marked
  historical on the next maintenance pass.
- The summary layer as a whole is regenerable from canonical layers.
- The index is consistent with the set of pages actually present.
- Every page is listed in the index under its page-kind section,
  exactly once.
- Every page-kind section header in the index corresponds to a
  page-kind that has at least one page.

## Explicitly excluded

- Not a source of truth for any decision.
- Not triggered by consumer queries (reads are passive). Maintenance
  is the only writer, and maintenance is triggered by content
  thresholds, not by consumer requests.
- No authoritative role in proposer judgment.
